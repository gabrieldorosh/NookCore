# Cosmetic lifetime travel — disabled prototype

This branch is a development checkpoint. It is separate from the current games candidate and must stay disabled until an occupied-vehicle Paper/client test passes. No server was launched and no production data was read.

`travel.lifetime-milestones.enabled` defaults to `false` in `config.yml`. The two configurable goals are `road-mount-blocks: 1000` and `rail-blocks: 1000`. Definitions are installed from the separate `travel-advancements.yml`; existing advancement and game catalogues are preserved. IDs are `nikosnook:travel/a_familiar_road` and `nikosnook:travel/on_the_rails`, with permanent `complete` criteria. There are no currency rewards or reward-map edits. If goals change, edit the descriptions separately to match.

The tracker samples every five ticks and counts horizontal distance only for visible Survival players in an Overworld environment. Hidden staff and vanished players are excluded. Road mounts use the existing configured GroundedTravel mount/material lists and collision tops, with an additional check across every ground column touched by the actual mount footprint. The first seated player must be on a tamed, saddled mount, grounded and outside water. Rear camel passengers, unsupported mounts and empty carts cannot count. Rail travel requires an occupied rideable cart and rail block data under its sampled route; the API has no direct `isOnRails` getter in this dependency. Slopes/curves and road stairs may undercount under these conservative checks. Neither movement speed nor jump strength is an achievement measurement.

World, vehicle, category, mode and mount changes break continuity. Player/vehicle teleports, respawns, deaths, dismounts, reconnects and restarts discard connectors. Large movement, non-finite/out-of-range coordinates, gaps over ten ticks or one second, and speeds above the bounded sampling envelope are discarded. Block checks inspect loaded chunks only and never generate/load terrain. Counters retain millimetres and fractional sample carry; no previous position is persisted.

Distance loads and saves use a background writer and narrow synchronized NookStore methods. A transaction contains at most 64 absolute, monotonic snapshots; repeating a minute/quit/shutdown save cannot add the same distance twice. Normal flushes run once per minute, plus quit and shutdown. A crash can lose the unflushed fraction of that minute. Shutdown waits up to ten seconds for queued saves and logs failures. The shared SQLite transaction boundary can briefly serialize other store work during a small batch; there is no per-sample database query or write. This assumes one tracker owns a player's counters in one server process.

Milestones are attempted only after a threshold is durably saved and the player is eligible. Minecraft's saved criterion makes retries after reconnect/restart idempotent; an already earned criterion does not create a new toast or celebration. Cosmetic failure does not alter money or pause games, shops or quests.

Before enabling in any owner fixture, test real player steering on full blocks, dirt paths, permitted slabs/stairs and rail curves/slopes; rear-seat/empty-vehicle exclusions; all hidden-staff transitions; unloaded boundaries; small and large player/vehicle teleports; quit/restart while a save is queued; both threshold crossings; and unchanged balances/ledger. Verify that an earned criterion is not announced or celebrated again after restart. There is deliberately no server-launch helper in this checkpoint.

API checked: installed Paper 26.2 build126 signatures (`Entity.getPassengers`, `AbstractHorse.getInventory`, `Entity.getBoundingBox`, minecart and teleport APIs), plus [Paper entity documentation](https://jd.papermc.io/paper/26.2/org/bukkit/entity/Entity.html). Runtime compatibility with the owner's Paper26.3 instance remains to be proved.
